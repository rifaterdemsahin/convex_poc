# Convex Schema

TypeScript-first schema definition for the Convex.dev PoC.

## `convex/schema.ts`

```typescript
import { defineSchema, defineTable } from "convex/server";
import { v } from "convex/values";

export default defineSchema({
  messages: defineTable({
    text: v.string(),
    author: v.string(),
    channel: v.optional(v.string()),
  })
    .index("by_channel", ["channel"])
    .index("by_author", ["author"]),

  users: defineTable({
    name: v.string(),
    email: v.string(),
    clerkId: v.string(),
    avatarUrl: v.optional(v.string()),
  }).index("by_clerk_id", ["clerkId"]),
});
```

## Schema Highlights

| Feature | How it works |
|---------|-------------|
| `v.string()` | Runtime validator — Convex rejects wrong types automatically |
| `v.optional(v.string())` | Field is not required — `undefined` is valid |
| `.index("by_channel", ["channel"])` | Enables efficient `q.withIndex("by_channel")` queries |
| `_id` | Auto-generated by Convex — unique document identifier |
| `_creationTime` | Auto-set by Convex — milliseconds since epoch |

## Why TypeScript-First?

The `v.` validators generate TypeScript types automatically. This means:

```typescript
// This is a compile error — Convex catches it before runtime
const bad = await ctx.db.insert("messages", {
  text: 42,  // Error: Type 'number' is not assignable to type 'string'
  author: "alice",
});
```
